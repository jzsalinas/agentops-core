# Minimal proposal format

Return these items without writing into the assessed project:

1. **Observed project:** relevant files, languages, test conventions, existing
   instructions and equivalent controls; unknown or bounded-out evidence.
2. **Recommendation:** no adoption, deferred, or a small selected documentary scope.
   Explain the concrete benefit and cost. Do not invent formal conformance levels.
3. **Source gate:** configured channel, publication status, version, immutable source
   commit, artifact digest and independently adopted trust anchor/evidence. Identify
   missing evidence. A real published prerelease needs explicit acceptance. An
   unpublished draft cannot fill a release pin even with owner interest.
4. **Proposed patch:** exact target paths and insertions preserving existing text,
   selected pinned guidance, policy/instructions references and existing decision
   record location. Pending placeholders must be visibly non-adoptable. If source
   pins are missing, present a contingent patch, not ready-to-apply instructions.
   Select the smallest useful files from the authenticated artifact without
   executing them. Include their exact bytes in the proposed diff and map original
   artifact paths and file digests to intended local paths in the existing adoption
   record. Preserve required notices. No local copy occurs during diagnosis. A
   version/digest assertion without the selected payload and mapping is incomplete.
5. **Validation and reversal:** inspect the diff, preserve instruction precedence,
   validate selected contract fixtures if applicable, verify references and pins,
   and confirm no services or permissions were activated. Reversal of documentary
   edits is an owner-reviewed diff; operational state would require its own plan.
6. **Approval needed:** exact changes, selected source and scope, remaining gates
   and separate operational activation if ever relevant. No permission expansion
   is implied by adopting guidance.

After approval, record adoption in the project's existing decision process. Verify
the applied diff matches approval. Use a short router in existing instructions
rather than duplicating policies. A discovered skill folder is optional and needs
its own approved location and actual host loading check. A project may use the
documents manually without installing a skill.
