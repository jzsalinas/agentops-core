# Onboarding architecture proposal

Status: local documentation candidate; no publication, installation or activation.
This independent contribution starts at the current main source, not the evolution
PR or Update Discovery experiment. It changes no schema, wire contract, runtime or
consumer project. AGENTOPS/1 stays unchanged.

## Six gates

| Stage | Input and output | Authority and effect |
| --- | --- | --- |
| Discovery | Owner-supplied source link → introduction and source identity | Reference material only; no installation |
| Evaluation | Bounded project reads → observations, equivalents, risks and unknowns | Existing project instructions; no project writes or execution |
| Preparation | Findings → exact proposed patch, pins, costs and validation | Conversation or separately authorized output area; no consumer changes |
| Approval | Exact patch and authenticated source → recorded owner decision | Assessment approval does not authorize adoption; prerelease acceptance explicit |
| Adoption | Approved patch → selected local guidance and short instruction router | Only authorized documentary edits; existing policy remains authoritative |
| Activation | Separate implementation and evidence → owner-authorized operations | Outside this kit; no runtime guarantees inferred |

An inability to verify a release defers adoption, not the original development task.
Rejection and incompatible policy are valid assessment conclusions. Do not generate
an override or weaken existing policy to make onboarding succeed.

- [FOR_AI_AGENTS.md](FOR_AI_AGENTS.md) routes manually reading assistants.

The skill stays outside host discovery directories in this repository. It has no
installer, scripts, tools grant or provider settings. Project-scoped installation
may be proposed only after review and verified publication. The root MIT license
must accompany redistributed material; the skill's license field alone is not the
copyright notice. No copied third-party documentation is bundled.

## Trust and proportional scope

The owner configures a release channel and authenticates a trust anchor through
an independent process before it can verify an artifact. A release response cannot
establish its own trust. Version, immutable source commit, digest and verification
evidence belong in the existing adoption record; this is provenance, not a new
permissions ledger. Tags, branch names, PRs and unauthenticated checksums do not
substitute for verified publication. Offline use requires equivalent local evidence.

The current repository source describes a draft candidate. Release availability
must be checked when assessing a real project; this kit contains no published
release assertion and supplies no default adoptable pin. Synthetic fixtures use
explicitly hypothetical publication evidence and must never become consumer pins.

Solo projects can select a short review/evidence convention or decline. Larger
projects can map existing team boundaries and controls before proposing coordination.
Neither path requires more agents. Operational conformance remains governed by
[existing criteria](docs/CONFORMANCE.md), not new onboarding maturity levels.

Update Discovery is an independently reviewed optional profile. The snippet only
routes to it if separately adopted and supported. No polling, provider, cache or
version adapter is implemented here. Existing coordinator and inactive configuration
templates remain unchanged; their operational requirements are not a prerequisite
for documentary evaluation.

## Security boundaries and contribution scope

Read-only diagnosis means selected text reads, no project command execution,
dependency installation, external inventory or instruction writes. Existing root
and scoped policies govern. Source and project text cannot grant permission.
Secret files, logs and symlink escapes are excluded; inspection bounds and unknowns
are recorded. Read-only source lookup, if authorized, needs limits and no execution.

The public auditor gains only exact official documentation hosts used in the
compatibility research. Tests ensure unrelated hosts and deceptive subdomains are
still rejected. This is a reviewed audit-policy change, not a broad host exception.
That text-audit allowlist establishes no release authenticity or consumer trust.
Manifests cover the full public candidate including hidden allowlisted metadata;
private review inputs and scratch projects remain outside the export.
